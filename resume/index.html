Project descriptions (STAR format)

For each portfolio project, the STAR (Situation, Task, Action, Result) breakdown. Use these verbatim or adapt to your actual context.

Project 1 — Enterprise Knowledge Intelligence Agent (GraphRAG)

SituationB2B SaaS with 50,000+ documents across SharePoint, Confluence, Notion, and S3. Customer success, sales engineering, and compliance teams all needed cross-document answers; naive vector RAG could find similar text but couldn\'t connect entities or pass compliance review.
TaskDesign and deliver a knowledge intelligence agent capable of multi-hop questions ("which customers are affected by clause X in template Y") with explainable, source-cited answers.
ActionArchitected an ingestion pipeline that builds both a Neo4j knowledge graph (ontology-constrained, provenance on every fact) and a vector index. Implemented three-lane hybrid retrieval (vector + BM25 + graph traversal) with cross-encoder reranker. Enforced evidence-first answer schema; added LLM-as-judge groundedness checks; instrumented full traces via Langfuse.
Result~70% hallucination reduction on labeled eval set. Customers receive answers with both citations and a graph traversal path, satisfying enterprise compliance reviews. Closed two enterprise deals that previously stalled on "show us how the AI explains itself."

Project 2 — Multi-Agent Operations Workflow (LangGraph)

Situation200 weekly customer escalations averaging 6 hours each. The customer success team\'s capacity grew linearly with revenue; the budget didn\'t.
TaskBuild a multi-agent system that handles routine escalations end-to-end with human approval gates on irreversible actions, while preserving full audit for compliance.
ActionDesigned a supervisor → worker LangGraph (research / planner / reviewer) with explicit termination logic and max-iteration budgets. Postgres-backed checkpointing supported multi-day HITL gaps. Every write tool routed through approve / edit / reject gates with idempotency keys. Daily eval against 100 historical cases.
ResultMean time to resolution dropped from 6h to ~45m. 95% reviewer-approval rate on agent-proposed actions. Full audit trail of every node, tool call, and approval — passed two compliance reviews.

Project 3 — MCP Tool-Augmented Agent

SituationFour agents on four different frameworks (LangGraph, Microsoft Agent Framework, CrewAI, Claude Desktop) each maintained their own Postgres, Slack, GitHub, and Stripe integrations — 16 duplicated implementations.
TaskEliminate duplicated integrations and unify security review without forcing all agents onto one framework.
ActionBuilt four MCP servers (postgres, slack, github, stripe) with scoped, read-only-default tools, per-server OAuth/mTLS auth, idempotency keys, and a unified audit log. Replaced 16 framework-specific integrations with 4 reusable MCP services.
ResultNew integration cost dropped from 4-agents × 1-week to 1× 2-weeks. Security reviews consolidated from 4 to 1. Future framework migrations no longer touch integration code — estimated 6 engineering weeks saved per migration.

Project 4 — Databricks Ask-to-Query Agent

SituationFinance and operations teams had a 5-day backlog with the 2-person data team. CFO wanted business users to ask questions in English without sacrificing governance over a 10TB+ warehouse.
TaskBuild a Text-to-SQL agent that\'s safe enough for production: no destructive SQL, no PII exfiltration, no runaway scans, full audit trail.
ActionImplemented schema-aware generation against Unity Catalog views (never base tables). Layered validation: SELECT-only parsing, allowlisted view references, LIMIT injection, dry-run cost estimation. Approval gate for queries above 1GB or novel patterns. Results landed in Delta with a complete run registry.
ResultAd-hoc query turnaround from 5 days to ~60 seconds. Zero security incidents. Cost p99 held under budget through dry-run gating. Data team reallocated from triage to high-value pipeline work.

Project 5 — LLM Evaluation & Observability (Langfuse)

SituationThree agents in production. Quality issues surfaced via customer complaints weeks after model or prompt changes. No systematic way to know if changes regressed.
TaskEstablish observability + evaluation discipline that catches regressions before customers do.
ActionAuto-traced every agent with Langfuse. Curated 200-case labeled eval datasets per agent. LLM-as-judge evaluators calibrated against humans (>85% agreement). Three-tier eval pipeline: CI smoke (2 min), nightly regression (15 min), shadow deploy (5% live traffic). Prompt registry for versioned config-deploy changes; auto-rollback on regression.
ResultCaught a model-provider update regression before 100% rollout — single incident prevented. Cost spike detected within 5 minutes via p99 alerts. Closed two enterprise deals where security review specifically required "show us how you monitor your AI."
