LLM Evaluation & Observability

The control plane for every other agent. Traces, evals, experiments, cost/latency — so you ship with discipline instead of vibes.

Prerequisites: M9 · M10 · Build time: 3–4 engineering weeks

Problem statement

Your team has 3 agents running in production. Quality is "fine" — until it isn\'t. The LLM provider updates a model and quietly degrades performance. An engineer tweaks a prompt and breaks citation coverage. Cost p99 spikes on a particular customer\'s usage pattern. You find out via customer complaint three weeks later. The fix is observability + evaluation discipline as a system, not an afterthought.

Why a founder builds this

  • Ship with confidence. Every prompt or model change passes through a labeled regression check. Regressions don\'t reach production.
  • Cost control. p50 and p99 cost-per-task tracked; per-tenant budgets enforced; spikes alert before the bill arrives.
  • Compliance posture. Every agent decision is a queryable trace. "Show me what happened on this transaction" — answered in 30s, not 3 days.
  • Closes enterprise deals. Security reviews always ask "how do you monitor your AI?" Having a real answer wins the deal.

Architecture

Component breakdown

ComponentModule(s)What it does
Auto-tracing SDKM10Every agent wired with Langfuse SDK at startup. LLM calls, retrievals, tool calls, sub-chains traced automatically.
Eval datasetsM10Per agent: 200-case labeled set (questions + expected outputs / criteria). Curated + reviewed quarterly.
LLM-as-judge evaluatorsM10Per signal (groundedness, citation coverage, task success). Calibrated against humans on 50 cases; >85% agreement required.
Smoke test (CI)M1030-case subset runs on every PR. ~2 min. Merge gated on no regression vs main.
Nightly regressionM10Full 200-case eval runs nightly. Compare to 7-day rolling baseline. Alert on drift.
Shadow deployM10Candidate prompt/model gets 5% of real traffic. Live scores compared. Auto-rollback on regression.
Prompt registryM10Versioned prompts referenced by name. Deploying a new version is a config change, not a code release. Rollback in seconds.
Cost & latency monitorsM10p50 + p99 tracked per agent, per tenant, per prompt version. Hard budgets per task. Alerts on spike.
Trace explorerM10Search by trace_id, user_id, score range, prompt version. Find the failing span in 30s.
Weekly reviewM1030-min team meeting: trends, escalations, anomalies. Production incidents become eval cases.

Design decisions you can defend

  • Three eval tiers, not one. CI smoke is fast (won\'t block PRs); nightly is thorough; shadow deploy is live. Each tier catches a different class of regression.
  • 5 signals, not 18. Force-rank what drives ship decisions: task success, schema validity, one quality signal (groundedness for RAG), cost p99, latency p99. More than five and the team stops looking.
  • LLM-as-judge calibrated against humans. 50 human-labeled cases; agreement must exceed 85%. Without this, "scores" are noise.
  • Different model as judge. GPT judging GPT is lenient; cross-model judging avoids that bias.
  • Prompt registry is mandatory. Every prompt change is a versioned config deploy. Rollback in seconds; old versions retained.
  • Shadow deploy before rollout. Catches what evals miss — production input distribution is always different from labeled sets.
  • Weekly human review. Production incidents become eval cases. The dataset grows with reality.

Failure modes & mitigations

Failure modeMitigation
Eval dataset doesn\'t match production distributionSample production traces weekly; add representative cases to dataset; quarterly review.
LLM-as-judge is too lenientPeriodic recalibration against humans; cross-model judges; track judge agreement rate as its own metric.
Score gaming (engineers tune to the eval set)Hold-out set never used for tuning; rotate eval cases; reward "production quality" not "eval score."
Cost spikes from runaway agentHard per-task budgets at agent layer; cost p99 alerts < 5 min; per-tenant rate limits.
Eval pipeline becomes slowTiered pipeline (CI smoke 2 min, nightly 15 min, comprehensive 1 hour). Don\'t conflate them.
Langfuse / provider outageBuffer traces locally if upstream is down; lose telemetry briefly but agents stay up; backfill on recovery.
Dashboard fatigue (no one looks)One dashboard, 5 metrics, weekly 30-min review. If a metric never drives a decision, drop it.

Interview / investor / customer talking points

Q: An LLM provider updates a model. What\'s your process?
A: Three-stage rollout. (1) Run our 200-case eval dataset against the new model — pin down quality delta on every signal. (2) Shadow deploy: 5% of production traffic to new model, compare live scores side-by-side for 2-3 days. (3) Gradual rollout if both pass: 25% → 50% → 100%, auto-rollback on regression. Whole process takes about a week. Without this, you find out via customer complaints — wrong feedback loop.
Q: How do you make sure your eval set actually reflects reality?
A: Three feedback loops. Sample production traces weekly and add representative new cases. Production incidents (customer complaints, edge cases) get added immediately. Quarterly review of full dataset for staleness. Hold-out set never used for tuning, so we know honest performance, not gamed performance.
Q: Why Langfuse over LangSmith or Helicone?
A: Open source + self-hostable was the deciding factor. We control our trace data — critical for regulated customers. The feature set across the three is similar; the implementation underneath is what matters for trust. LangSmith is the closest comparable; if we were heavier on LangChain we\'d weigh it harder. Helicone is great for cost-focused use cases. For us, Langfuse balanced flexibility, control, and feature depth.
Q: A board member asks for ROI on the observability investment.
A: Three signal-of-value moments. (1) Caught a model regression in shadow deploy that would have hit 100% of users — single incident avoided saves the equivalent of a customer-success quarter. (2) Pinpointed a runaway agent loop within minutes via cost p99 alerts; without observability we\'d have learned at month-end via the invoice. (3) Closed two enterprise deals where the security review specifically asked "show us how you monitor AI" — having a real answer was the differentiator. ROI is loose because these are tail-risk and revenue events, but each one pays back the entire investment many times.
