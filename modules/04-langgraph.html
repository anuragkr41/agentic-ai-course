1. Why graphs (and not chains)

A chain is linear: A → B → C. A graph has nodes (steps) and edges (transitions), and edges can be conditional or cyclic. ReAct (Module 2) is literally a cyclic graph. So is any agent that retries, loops, branches, or waits for a human.

You need a graph when any of these is true:

  • Conditional routing. "If the LLM said X, go to node A; otherwise B."
  • Loops. ReAct cycles. Reflection loops.
  • State persistence. You need to pause execution and resume later (e.g., for HITL).
  • Concurrent paths. Two workers running in parallel, then converging.

2. State schema & reducers

In LangGraph, State is the data that flows through the graph. You define its shape (a TypedDict or Pydantic model) up front. Every node reads State and returns updates. 

from typing import TypedDict, Annotated
from operator import add

class AgentState(TypedDict):
    messages: Annotated[list, add]   # reducer: append
    refund_proposal: dict | None      # reducer: replace (default)
    iterations: int

A reducer tells LangGraph how to merge a node's output into existing state. The default replaces the field. add appends to a list. You can write custom reducers (e.g., union sets, max-of). Reducers are why graph state behaves correctly under branching and concurrent updates.

3. Branching, checkpoints & replay

Checkpoints are snapshots of State after each node. They unlock four superpowers:

  • Pause / resume. Stop the graph mid-execution; resume later from the last checkpoint.
  • Replay. Re-run from any checkpoint with the same inputs — perfect for debugging.
  • Fork. Branch from a checkpoint with different inputs — A/B test prompts against the same prior state.
  • Time travel. Step backward through checkpoints to see exactly where things went wrong.

A checkpointer is a backend (in-memory for dev, Postgres or Redis for production). It writes a checkpoint after every node. Cost is one DB write per step — usually negligible.

4. Human-in-the-loop interrupts

LangGraph's killer feature for safety-conscious founders: interrupt. A node can call interrupt(payload) mid-execution. The graph pauses, persists state, surfaces the payload to a human. When the human responds (via your UI / API), the graph resumes from exactly where it stopped. 

def propose_refund(state: AgentState):
    proposal = build_proposal(state)
    decision = interrupt({"propose": proposal, "options": ["approve", "edit", "reject"]})
    if decision == "approve":
        return {"refund_proposal": proposal, "status": "approved"}
    elif decision["action"] == "edit":
        return {"refund_proposal": decision["edited_proposal"]}
    else:
        return {"status": "rejected"}

5. Memory: short vs long term

Short-termLong-term
ScopeSingle thread / conversationAcross threads / users
ImplementationState / checkpointsExternal store (vector DB, KG, SQL)
Example"What did the user say 3 messages ago""User's product preferences over months"
CapacityBounded by context windowEffectively unlimited

LangGraph has a Store abstraction for long-term memory. Read it at the start of a turn, write to it at the end. Common pattern: vector store keyed by user_id for semantic recall, plus relational rows for facts.

6. Deployment patterns

  • LangGraph Platform. Managed deployment with persistence, threads, HITL endpoints, monitoring. The easiest path; useful even if you self-host eventually.
  • Self-host. Run as a server (FastAPI / Express) with Postgres as the checkpointer.
  • Embedded. Inside another app, in-memory checkpointer. Use only for short-lived sessions.

Likely interview / investor / hiring questions

Q: When would you reach for LangGraph instead of plain LCEL?
A: As soon as I need any of: stateful variables across steps, conditional routing, loops (including ReAct), parallel branches that converge, or a pause/resume mechanism for HITL. LCEL is fine for stateless linear pipelines. For everything else LangGraph saves you re-implementing state machines yourself.
Q: What's a reducer and why does it matter?
A: A reducer is the merge function applied when a node returns updates to State. Default replaces; add appends. They matter because branching and parallel nodes both write to State — without reducers you get last-write-wins bugs or silent overwrites. Specifying the right reducer per field is a 5-minute design step that prevents 5 hours of debugging.
Q: How does LangGraph interrupt differ from "just check a database flag in a loop"?
A: Interrupt persists exact state and gives you replay/fork for free. A polling-loop pattern loses execution context, can't safely replay, and doesn't scale across server restarts. Interrupt is also natively integrated with checkpointing, so the pause is durable — survives crashes, deployments, and weekend gaps. This is the difference between a demo and a production HITL system.
