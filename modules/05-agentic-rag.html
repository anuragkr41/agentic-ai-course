Why this matters

Traditional RAG is "embed query → top-k chunks → stuff into prompt → hope." It works for easy questions. It fails for ambiguous queries, multi-hop reasoning, and anything where the right answer requires the agent to decide how to retrieve, not just retrieve once. Agentic RAG fixes that — the agent rewrites queries, picks retrieval strategies, reranks, and grounds every claim in evidence.

2. Adaptive retrieval strategies

The agent picks the strategy per query:

  • Skip retrieval. If the question is parametric ("What's 2+2?"), don't retrieve. Saves cost and latency.
  • Single-shot. Standard top-k. Good for direct factual questions.
  • Multi-query. Generate N rewrites of the question, retrieve for each, union. Better recall for ambiguous queries.
  • Step-back. Generalize the question first ("What's the company's refund policy" → "What's the company's customer service policy"), retrieve the broader context, then narrow.
  • Hypothetical document (HyDE). Have the LLM generate what an answer would look like, embed that, retrieve. Counter-intuitively powerful for novel queries.

3. Query rewriting + reranking

Rewriting turns user noise into clean queries. "ugh my order from like last week is broken can u fix it" becomes "Refund or replacement request for order placed approximately 7 days ago." The clean query embeds better.

Reranking re-scores the top-50 retrieved chunks with a stronger model (Cohere Rerank, Voyage Rerank, or a cross-encoder). You keep the top-5 from that. Cost: one extra API call. Benefit: typically +15 to +20 points on answer quality.

4. Evidence-first answers

The rule: no claim without a citation. Force the LLM to ground every fact in a retrieved chunk via structured output:

class Answer(BaseModel):
    text: str
    citations: list[Citation]  # required, non-empty
    confidence: float

class Citation(BaseModel):
    chunk_id: str
    quote: str  # exact span from the chunk
    relevance: float

If the model can't cite, it must say "I don't have that information." This single rule reduces hallucination by 60–80% on retrieval-heavy tasks.

Likely interview / investor / hiring questions

Q: How do you prevent hallucination in a RAG system?
A: Three layers. (1) Evidence-first output schema — every claim must include a citation to a retrieved chunk; if the model can't cite, it must say "I don't know." (2) Groundedness check post-generation — an LLM-as-judge call asks "is this claim supported by these chunks?" If no, retry or escalate. (3) Continuous eval on a labeled set tracking groundedness, citation coverage, faithfulness — so you catch drift before users do. Together: ~80% reduction in confident-wrong outputs.
Q: When is reranking worth the extra cost?
A: Almost always, on non-trivial corpora. Reranking adds one API call (~$0.001 per query) and typically lifts answer quality 15-20 points. The exception is when your top-5 is already near-perfect — measure recall@5 before adding rerank. If it's already 95%+, skip the rerank.
